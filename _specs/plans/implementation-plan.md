# Plan: PimcoreComparisonBundle — seed `_state` + build the bundle

## Context (why)

`skeleton/bundles/PimcoreComparrisonBundle` (note the double-r typo in the dir) is a **concept-only**
bundle: it holds `_specs/base-idea.md` (Draft v0.1 — a Studio view that diffs *two* data objects of
the same class, closing the gap Pimcore's single-object version-compare leaves) plus a `_state/`
directory **copied wholesale from the Portal Engine bundle**. Every `_state` file therefore describes
the wrong bundle (Portal features, Portal spec IDs, Portal parity rows; `pw.json`/`junit.xml` even
hardcode `PimcorePortalsBundle` paths and 181 passing Portal tests).

Two deliverables:
- **Part A** — replace the borrowed Portal `_state` with the Comparison bundle's real state.
- **Part B** — a concrete implementation plan to build the bundle from `base-idea.md`.

### How the `_state` registry actually works (confirmed by tracing the Portal generators)

`_state/` is **generated, never hand-edited** ("declaration is authored, state is computed"; CI runs
`git diff --exit-code _state/` to enforce it). It joins authored sources with test evidence:

| Authored source | Feeds | Generator |
|---|---|---|
| `#[AsFeature(id,group,name,description,status,specRefs,dependsOn,since,backendOnly)]` on impl classes | `features.yaml`, `coverage.yaml`, `FEATURES.md` | `…:features:state` |
| `#[CoversFeature('id')]` on tests + `@feature:id` in Playwright titles | per-feature pass/fail counts | `…:features:ingest` |
| requirement IDs in `_specs/**/*.md` (regex `FR-[A-Z]+-\d+ \| C-\d+ \| T-SEC-\d+[a-z]? \| T-ARCH-\d+ \| T-FEAT-\d+ \| E2E-[A-Z]+-\d+`) | `spec-coverage.yaml` (claimed vs orphaned) | `…:features:state` |
| `ParityMatrix::rows()` (static PHP array) ⋈ playwright/junit | `parity/matrix.{yaml,md}` | `…:parity:state` |
| `APPENDIX-D-*.md` allow-list ⋈ `@internal` imports scanned from `src/` | `contracts/internal-contracts.md` | `…:architecture:internal-contracts` |

`FeatureStatus` = `planned → in-progress → beta → stable (+ deprecated)`. `effective` status is
`declared` capped by evidence + a dependency fixpoint (no feature may outrank what it `dependsOn`).
For a bundle with **no code and no tests**, a real run emits essentially empty files.

### Decisions taken (from the user)

1. **Planned seed from concept** — hand-author `_state` to describe base-idea.md's features, every one
   `planned` with 0 tests, spec IDs all orphaned. Honest snapshot of a not-yet-built bundle; a real
   generation run later overwrites it.
2. **Derive a CMP taxonomy and author it into `_specs/`** so the IDs are real and machine-scannable.
3. **Reframe parity** as a greenfield capability matrix (drop the "Legacy surface" column).

## Part A — seed the `_state` directory

### A0. Header discipline (honesty)

The current files claim `# GENERATED by portalengine:features:state`. Writing "GENERATED by
comparison:features:state" would be a lie (no such command exists yet). Every seeded file gets an
honest header instead:

```
# SEED — hand-authored from _specs/base-idea.md + _specs/requirements.md.
# Not generated. Will be REPLACED by `comparison:features:state` once the registry generator is
# ported (Part B, Phase 7). Do not treat as computed evidence.
```

### A1. New authored source: `_specs/requirements.md`

Create `_specs/requirements.md` (leaves `base-idea.md` untouched) enumerating the requirement IDs the
seed references, each mapped to a base-idea section. IDs match the generator's scan regex exactly, so a
future real run reproduces `spec-coverage.yaml`. Note: the illustrative `T-SEC-CMP-*` from the Q2
options can't be used — the scanner's `T-SEC-\d+[a-z]?` prefix is fixed — so security IDs are plain
`T-SEC-nnn` (no infix); functional = `FR-CMP-nnn`, e2e = `E2E-CMP-nnn`, invariants = `C-n`.

**Core invariants (`C-*`)** — from Goals/Non-goals/§7:
- `C-1` same-class only (both Concrete, identical ClassDefinition)
- `C-2` field-level layout permissions enforced server-side; hidden fields carry no value
- `C-3` read-only in v1 (no merge/copy/write)
- `C-4` stateless (no object data persisted; ETag on the modificationDate pair)
- `C-5` thin client (diff computed server-side, one place for permission logic)
- `C-6` exactly two objects (n-way out of scope)

**Functional (`FR-CMP-001…`)** — from §6 components + §5 UX: ComparisonService orchestration;
FieldWalker over the layout tree; ComparatorRegistry (tagged/priority/first-wins); Scalar / TextDiff /
WYSIWYG / Relation / Localized / FieldCollection / ObjectBrick / ClassificationStore / Fallback /
asset-field comparators; normalization rules; status taxonomy; DiffResult DTO; filters; summary counts;
swap + language selector; section pagination; the 3 REST endpoints; XLSX+JSON export; comparator SPI;
Pre/PostComparisonEvent; bundle config. (~24 IDs.)

**Acceptance (`E2E-CMP-001…`)** — the entry points and view behaviours from §5 (grid-multiselect →
compare, toolbar compare-with, deep link, differences-only filter, inline text diff, localized per-lang
rows, relation add/remove/reorder chips, container expand, export download, permission-hidden row).

**Security/architecture/registry gates** — `T-SEC-001..00n` (permission parity, `plugin_comparison`
gate, no-persist, no-write route, export honors filter), `T-ARCH-001..00n` (import boundaries,
`@internal` audit, frontend purity), `T-FEAT-001..006` (the registry gates themselves, if Part B ports
the discipline).

## Part B — implementation plan for the bundle

### Backend reuse (confirmed — do NOT reinvent)
- **Per-fieldtype diff API already exists** on `Pimcore\Model\DataObject\ClassDefinition\Data`
  (`vendor/pimcore/pimcore/models/DataObject/ClassDefinition/Data.php`): `getDiffDataForEditMode()`
  (normalized rows, auto-dispatches to `getDiffVersionPreview()` per concrete type), `getVersionPreview()`
  / `getForCsvExport()` (string render — Studio already uses these in
  `studio-backend-bundle/src/DataObject/Service/DataService.php`), and `EqualComparisonInterface::isEqual()`
  (guard with `instanceof`) for change detection. Relation/Localized/Fieldcollection/Objectbrick types
  override the diff-preview; **Classificationstore does not** (walk its `getActiveGroups()`/`getItems()`).
  → the `FallbackComparator` is literally `getVersionPreview()`; comparators wrap these, not hand-rolled logic.
- **Layout-tree walk**: copy core's own recursion `ClassDefinition::extractDataDefinitions()` over
  `getLayoutDefinitions()->getChildren()` (branch `instanceof Layout` container vs `Data` leaf); nested
  defs via `Localizedfields::getFieldDefinitions()`, `Fieldcollection\Definition::getByKey()`,
  `Objectbrick\Definition::getByKey()`.
- **Field/language permissions are already server-side**: resolve the per-user layout with
  Studio `DataObject\Service\LayoutService::getDataObjectLayout()` (enforces custom-layout permission +
  `ForbiddenException`), which calls core `DataObject\Service::enrichLayoutDefinition($layout,$object,[],$user)`
  → `enrichLayoutPermissions()` sets per-field `setPermissionView/Edit`. Diff only the leaves that survive
  → satisfies C-2 with **zero new permission code** (the `hidden` status is "no view permission").
- **Template bundles to copy**: `PimcoreCollaborationBundle` (smallest complete Studio REST controllers
  extending `AbstractApiController` + a React plugin) and `PimcoreDataSpineExplorerBundle` (bundle-local
  abstract controller + `Security\SpinePermissions` layer — the model for `plugin_comparison`).
  NOTE: `GartnerMdmDemoBundle` does NOT exist under `bundles/` — do not template on it.

### Frontend: the design (screens) → Studio SDK components
Source of truth for the layout: the Claude Design `Comparison View.dc.html` (project
`8b608c34-…`). **Its bundled "pimcore-design-system" is a marketing-mock approximation (Inter font,
Lucide icons, `--pc-*` CSS vars) — NOT the SDK.** Per the user's hard constraint, the build reproduces the
*layout and behaviour*, but every element is a real Studio UI SDK component with SDK theme tokens + the SDK
`Icon` component (drop Lucide + `--pc-*`). SDK stack (confirmed from CollaborationBundle / DataSpineExplorer):
React 18 + Ant Design 5.22 shared-singleton + `@pimcore/studio-ui-bundle` components; see the mapping table
below (exact SDK export names read from `vendor/pimcore/studio-ui-bundle/assets/js/src/components` at build).

Three screens the design defines:
1. **Entry 1 — grid multi-select → context menu.** Studio data-objects listing; a context-menu action
   "Compare objects", enabled only when exactly two rows of the *same class* are selected (else disabled
   with a tooltip). → register a grid selection/context-menu action via the SDK module system.
2. **Entry 2 — "Compare with…" dialog** from the object-editor toolbar: an SDK `Modal` with an object
   search pre-filtered to the same class (SDK search input + result list), Cancel / Compare. Plus the deep
   link `/studio/comparison?left={id}&right={id}` (SDK route registration + copy-to-clipboard).
3. **Comparison view (main panel)** — an SDK widget/panel, top-to-bottom:
   - **Header**: compare icon + "Compare objects", the deep-link pill (mono + copy), "Class: X · read-only (v1)".
   - **Two object cards** (LEFT · swap · RIGHT): key, published/draft **Tag**, path, "ID · modified · by",
     circular **swap** button between them.
   - **Toolbar**: **Segmented** filter (All / Differences only / Equal only), field free-text **Input**,
     **Language** toggle chips, expand-all / collapse-all icon buttons, **Export Dropdown** (XLSX / JSON,
     "honors permissions").
   - **Diff table** (virtualized; columns `Field | Left | Right | Status`, sticky header): collapsible
     **section** rows from the layout tree (General/Descriptions/Pricing/Relations/Media, + tagged
     Field-collection / Object-brick / Classification-store sections); nested **item** rows (field-collection
     items, "matched by index (v1)"); **field** rows whose Left/Right cells render one of: plain text
     (`—` for null), **inline token diff** (deletion strike-through / insertion underline), **relation
     chips** (kept / added / removed / **reordered**), **image** thumbnail + asset id/path, **hidden**
     ("Value withheld", lock) and **not-comparable** ("Calculated value failed"). Localized fields render
     one sub-row per language with a language badge; the language chips filter globally.
   - **Status taxonomy** (icon + color, color never the only signal): equal / changed / only-left /
     only-right / reordered / not-comparable / hidden — mapped to SDK semantic tokens (success/warning/
     danger/info/neutral), with an optional per-row status tint.
   - **Summary bar**: "N of M fields differ" + per-category counts; note "Computed server-side ·
     permissions enforced · nothing persisted".
   - **Toasts** via the SDK notification API (export ready, link copied).
   - Density comfortable/compact.

### Bundle skeleton (standard, installable)
`PimcoreComparisonBundle` class + `Installer` (registers the `plugin_comparison` permission), `composer.json`
(`pimcore/comparison-bundle`, ns `Pimcore\Bundle\ComparisonBundle`), PHPStan/CS/Rector, `config/` (services,
routes import), `_specs/`, `_state/`, `assets/` (Rsbuild React plugin), `tests/`.

### Backend pipeline (base-idea §6)
`ComparisonController` (REST, `AbstractApiController`, under `/pimcore-studio/api/comparison/...`, OpenAPI +
ProblemDetails) → `ComparisonService` (guards: both exist, both `Concrete`, identical ClassDefinition,
view-permission on both — C-1/C-6) → resolve per-user layout (LayoutService, above) → `FieldWalker`
(extractDataDefinitions-style) → `ComparatorRegistry` (tag `pimcore.comparison.field_comparator` + priority,
first-supporting-wins) → comparators {Scalar, TextDiff (+WYSIWYG sanitized-HTML), Relation, Localized,
FieldCollection, ObjectBrick, ClassificationStore, AssetField, Fallback} → `DiffResultAssembler` →
normalized `FieldDiff` DTO tree → JSON. `Pre/PostComparisonEvent`; stateless (C-4), ETag on the
modificationDate pair; endpoints `objects`, `objects/summary`, `objects/export` (XLSX/JSON honoring the
active filter — C-3, no write route).

### Confirmed Studio extension mechanics (copy `PimcoreDataSpineExplorerBundle`)
- **REST controller**: `AbstractComparisonController extends AbstractApiController` (injects
  `SecurityServiceInterface`, adds `requireComparisonAccess()`), `ComparisonController` with full-path
  `#[Route('/pimcore-studio/api/comparison/objects', methods:['GET'])]` etc. Query→DTO via
  `#[MapQueryString]` (needs the `controller.service_arguments` tag on the controller service). OpenAPI via
  `#[Get]/#[SuccessResponse]/#[DefaultResponses]` + a `Tags` enum. Errors = throw
  `StudioBackendBundle\Exception\Api\*` (e.g. `ForbiddenException`, `ElementNotFoundException`).
- **Routes**: `config/routes.yaml` (`resource:'../src/Controller/' type:attribute`) **plus** add
  `pimcore_comparison: resource:"@PimcoreComparisonBundle/config/routes.yaml"` to `skeleton/config/routes.yaml`
  (or use `config/pimcore/routing.yaml` to skip the app import). Anything under `/pimcore-studio/api/...` is
  inside the Studio auth firewall automatically.
- **Permission**: `PluginComparisonPermissions` catalogue (`plugin_comparison`), registered idempotently in
  `Installer` via `User\Permission\Definition::create()->setCategory()->save()`; enforce per-request with
  `SecurityServiceInterface::hasElementPermission($el,$user,'view')` on **both** objects.
- **Frontend plugin**: `assets/` Rsbuild + Module-Federation (name `pimcore_comparison`, expose
  `'.':'./js/src/index.ts'`, shared singletons react/react-dom/antd/inversify). `index.ts` default-exports
  an `IAbstractPlugin` (onInit → register widget + context-menu + nav; onStartup → module system). Host is
  consumed as an MF remote; the plugin-system auto-calls `registerPlugin`.
  - **Grid context action (Entry 1)**: `ContextMenuRegistry.registerToSlot('data-object.list-grid', {useMenuItem})`;
    `useMenuItem` returns `null` unless exactly two objects of the **same class** are selected → the
    "Compare objects" item; onClick opens the comparison widget with `{left,right}`.
  - **Widget/panel + deep link (Entry 2/3)**: `widgetRegistry.registerWidget({name,component})` for the
    Comparison view; `mainNavRegistry.registerMainNavItem`/a navigator for `/studio/comparison?left&right`.
  - **PHP entry point**: `src/Studio/WebpackEntryPointProvider.php` (glob `public/build/*/entrypoints.json`,
    `getEntryPoints()=>['exposeRemote']`) tagged `pimcore_studio_ui.webpack_entry_point_provider` **declared
    explicitly** and excluded from any `../src/*` prototype (prototype clobbering silently kills the plugin).
  - **API layer**: start with a plain-fetch client (`/pimcore-studio/api/comparison`, `credentials:'include'`)
    like DataSpine; optionally graduate to RTK-Query codegen injected into `@pimcore/studio-ui-bundle/api`.

### Gotchas to respect (CLAUDE.md / memory / agents)
Webpack entry-point tag is `pimcore_studio_ui.webpack_entry_point_provider` (underscores, not dots);
a `../src/*` services prototype clobbers the tagged entry-point/controller defs unless excluded or declared
after it; bundle routes need the explicit app import; console needs `php -d memory_limit`; **do not add a
client-subscribable Mercure topic** (browser 6-connection limit starves REST) — use polling/short-TTL; DB is
view-only. This bundle is read-only (C-3) → no object-write path at all.

## Testing (detailed — user requirement: PHPUnit for any functionality, Playwright in full detail)

Mirror the Portal bundle's split: `tests/Unit/**` (PHPUnit) + `tests/e2e/**` (Playwright), every test tagged
so the registry computes real coverage (`#[CoversFeature('<id>')]` on PHPUnit classes/methods;
`@feature:<id>` + the `E2E-CMP-nnn` id in Playwright titles). PHPUnit → `_state/junit.xml`; Playwright
`--reporter=json` → `_state/pw.json` (+ `pw-dist.json`).

**PHPUnit — exhaustive, one concern per test, golden fixtures per fieldtype:**
- `ComparisonService` guards: same-class pass, cross-class reject, non-Concrete reject, missing object,
  view-permission denied on either side (→ `hidden`/403). (C-1, C-6, T-SEC-001)
- `FieldWalker`: layout tree preserves panels/tabs/regions; localized/fieldcollection/brick/classification
  child defs are reached; permission-masked leaves are emitted as `hidden` with no value. (FR-CMP-002, C-2)
- `ComparatorRegistry`: priority ordering, first-supporting-wins, project override beats core.
- **One test class per comparator** with golden-file fixtures per fieldtype (Scalar, TextDiff, WYSIWYG-
  sanitized, Relation add/remove/kept/**reordered**, Localized per-language incl. translation-gap →
  `only-left`, FieldCollection index-match + only-right item, ObjectBrick, ClassificationStore via
  groups/items, AssetField id/path, Fallback via `getVersionPreview`). Each asserts `status`, `leftDisplay`,
  `rightDisplay`, `inlineDiff` tokens, `children`, `meta` counts.
- Normalization: trim, numeric epsilon ("13.4" == "13.40"), date UTC/precision, `""` vs `null`. (FR-CMP-014)
- `DiffResultAssembler` DTO shape; summary counts ("N of M differ"). Export XLSX + JSON honor the active
  filter and permissions (C-3). API functional tests for the 3 endpoints: payload shape, OpenAPI presence,
  ProblemDetails on bad input, permission gate, ETag on the modificationDate pair.

**Playwright — every screen and behaviour from the design, one spec per behaviour:**
- Projects: `api` (headless endpoint specs) + browser (`ui`) specs; `playwright.config.ts` + `global-setup`
  + storageState, run `--workers=1 --retries=2` (e2e contention gotcha).
- Entry 1: "Compare objects" appears **only** when exactly two same-class objects are selected (disabled/
  hidden otherwise). Entry 2: Compare-with modal filters to the same class, pick + Compare. Entry 3 / deep
  link: `/studio/comparison?left&right` renders; copy-link.
- Comparison view: filter All/Differences-only/Equal-only narrows rows; field free-text filter; language
  chips add/remove per-language sub-rows; swap flips sides (and `only-left`↔`only-right`); expand/collapse
  all; export XLSX + JSON actually download; summary bar counts.
- Diff rendering: inline token diff (ins underline / del strike), relation chips (added/removed/kept/
  reordered, reorder-only filterable as noise), image cell (asset id/path), field-collection index match +
  only-right item, `hidden` permission row (value withheld, as a non-admin tenant), `not-comparable` cell.
- Empty state ("No fields match the current filter"). Each browser assertion carries its `E2E-CMP-nnn` id.

Gate hygiene (memory): run PHPUnit **foreground** (backgrounding corrupts junit); Playwright JSON → `_state/`.
